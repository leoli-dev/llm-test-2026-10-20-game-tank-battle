# STEEL HORIZON · R4 独立试玩（HUD 独立栏 + 画布自适应）

**日期**：2026-10-20（同日 R3 之后）
**环境**：独立 Chromium（`/Applications/Chromium.app`，headless，Playwright 驱动）+ vite dev `127.0.0.1:5179`
**改动**：纯 UI/渲染层——HUD 全部移出画布、进入独立顶/底栏；画布独占中间舞台；相机/渲染器/瞄准/投影全部改用**实际画布区域**；ResizeObserver 真实 resize。**玩法、迷宫、AI、数值零改动。**

## 1. 布局改造（改了什么）

| 之前（R3） | 之后（R4） |
|---|---|
| HUD 绝对定位浮在画布四角（顶中横幅、底左 HUD、底右小地图） | `#topbar`（分数/信息/横幅/按钮）+ `#stage`（**只含画布**）+ `#botbar`（装甲/炮温/生命/敌军条/小地图）三段 flex 列，**任何尺寸下 HUD 与画布零重叠** |
| 相机按 `innerWidth/Height`（全屏）算距离与 aspect | `_syncCanvas()`：renderer 尺寸、camera.aspect 均取 `#stage` 实际像素；`_frameCamera()` 用包围球在**该 aspect 的垂直/水平 FOV 之间取更紧者**推距离——任何宽高比下 52m 战场四角都完整入画 |
| 鼠标 NDC 用 `innerWidth/Height` | 用 `canvas.getBoundingClientRect()` 换算 NDC（画布上方有 52px 顶栏，全屏坐标会系统性偏下） |
| `projectToScreen` 返回相对**窗口**坐标 | 返回**页面坐标**（canvas 矩形偏移 + NDC），与 `clientX/Y` 同一坐标系 |
| 小地图常开 118px 压住右下战场 | 默认收起；按钮切换，展开时占据底栏右侧（画布外），画布自动重排 |
| 横幅叠在画布正中 | 横幅在顶栏中间独立伸缩区（`#banner-zone` 内容自适应宽度，与左右两组不相交；≤820px 换整行） |
| 窗口 resize 只改 aspect，不改距离/画布 | window resize + ResizeObserver 双触发 `_syncCanvas()`（重设画布、aspect、相机距离） |
| ≤1000px 信息整行隐藏（丢失敌军数） | 窄屏只隐藏阶段名，「敌军 N/4｜击毁 n」保留；底栏敌军条旁另有 `N/4` 数字 |

**窄屏可读性**：分数 20px / 信息 11.5px / 按钮 ≥38px 高；菜单/暂停/结算卡片 `max-height:92vh` 可滚动且保证在窗口内。

## 4. 过程中两次失败与定位（如实保留）

1. **r4-layout 横幅断言假阳性（测试 bug，非产品 bug）**：`inter(a,b)` 判据期望 `{l,r,t,b}` 字段，却直接传入了原生 `getBoundingClientRect()`（字段是 `left/right/top/bottom`）→ `a.r` 恒 undefined → 恒判相交。独立 debug 脚本（先把 rect 转成 l/t/r/b 对象）显示四档尺寸下横幅盒体（254px 宽）与左右 HUD 组均**不相交**。修好判据后全部通过。**产品 CSS 未因该假阳性做错误改动**；同批落地的横幅 `#banner-zone` 居中容器是把"拉伸盒体+文字居中"改成"内容自适应盒体+外层居中"，属于更正确的实现，非修复假阳性。
2. **r3-smoke 时间推进检查超时（间歇帧停顿，偶发）**：`npm run test:all` 首跑在 smoke 的 `time+0.2s` 检查 10s 超时；随后单独重跑两次连续通过，判定为该环境既有的间歇停顿（R1/R2/R3 期间多次出现，未改时间步、未归因 GPU），给该检查与跨格检查加了与 `waitCombat` 一致的截帧/置顶唤醒重试。加后整链一次通过。

## 6. 已知限制

- **宽屏战场居中留白**：方战场放进横版画布时，无裁切的最大缩放由垂直 FOV 决定，左右留白是几何必然（如 1280×800 战场约占画布宽 40%）。这是"四角必须完整入画"约束下的最大缩放，实测坦克/砖可辨、命中正常，不算"小到没法玩"；若后续想填满宽度需要裁切战场或改投影。
- 间歇帧停顿仍可能让单条等待偶发变慢（现已有唤醒重试兜底）；根因未定，未归因 GPU。
- 768×1024 下顶栏占两行（104px），画布相应减高，属预期。
- 触屏/手柄仍不支持（键盘+鼠标优先）。
