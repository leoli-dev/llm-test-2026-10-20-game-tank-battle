## 三、失败/缺陷记录（不替代、不美化）

1. **点射冷却 bug（真实缺陷，已修复）**：隔 1s 短按 Space 70ms ×3，shots 停在 1、fireCd 0.33→0.247→0.18。根因：`fireCd` 扣减写在 `if ((mouse.down||Space) && ... && (fireCd -= dt) <= 0)` 短路链里，**松开后冷却不恢复**。修复：冷却改为每帧无条件随游戏时间扣减（暂停时 `_updatePlayer` 不执行，天然冻结）。独立复测：3 次 70ms 真实短按 shots=1→2→3、0 错误。未改射速/伤害。
2. **冒烟斜向小位移（未完全定位，未改游戏）**：W+A 斜向从出生格 (6,6) 出发 3s 仅位移 0.85m。当时断言“正西 (5,6) 是砖”有误——当前 `R3_MAP` 中 (5,6) 为空、(4,6) 才是砖；小位移的确切根因未定位（疑为砖角碰撞与帧时序的组合，未插桩确认，不直接定性）。改用正北单轴 W（(6,5) 确认为空）并等待实际跨格后查 goal，稳定通过。
3. **固定 sleep 脚本的“世界没推进”观察（原因未定位，未改游戏时间步）**：固定 Node sleep 型脚本多次观察到时钟停滞，而独立环境脚本（waitForFunction/waitForTimeout）稳定推进；停滞的确切原因未定位（不直接归因 GPU/环境）。按监督要求全部改为 `page.waitForFunction`（rAF 轮询等可观察状态）+ 超时截帧/置顶唤醒重试；**未**因单次异常改 dt/物理。
4. **转角计数判据 bug（测试缺陷，已修复）**：r3-maze-check 初版前向量取"当前→前一格"、后向量取"当前→后一格"，直路每步都误计转角。改为一致前进方向比较，并用直线(0)/两折(2)/四折(4)小样例核验后通过。
5. 地图 v1/v2 两次被监督否决（见上表）——如实保留，避免"只加墙不建巷道"的方向错误。

## 五、已知短板（如实）

1. 三局自测全胜偏易：bot 采用“最近敌锁定 + 持续按住空格连发 + 远距逼近/中距横走/近距后撤”策略，玩家 7m/s 对敌 4.6m/s 速度差明显，且 bot 瞄准无误差（真实鼠标投影到敌人身上）；真人反应/散布/被横走拉扯时中弹率会上升（无射击观察局已验证敌人能真实打出伤害）。未为通过测试调低敌人任何参数。
2. 迷宫为一次性生成 + 人工打断校准，**未做玩家视角可玩性 A/B**（如"是否过绕"）；仅以结构指标 + 实际行走 + 独立复核支撑。
3. 钢墙仅 4 格且远离玩家出生，战斗中主要作为地形锚点；"钢墙战术价值"未被对局数据验证。
4. 中央 2×2 交战口袋在实际对局中利用率不高（4 敌多在外圈回廊接敌）；保留为可选交战空间。
