# R4：pi 自述与独立证据核对

这份审计由监督者撰写，仅记录证据差异，没有修改游戏或 pi 文档。

- PLAYTEST-R4.md 的 r4-play 计为 7/7；脚本实际有 8 个 ok 调用产生 PASS（宽屏2、窄屏2、768按钮/卡片3、无错误1）。完整合并回归90行PASS是真实日志计数。
- PLAYTEST-R4.md 的画布高度未与最终 DOM 测量核对：默认地图关闭时1440×900实际画布1440×788（文档792），1280×800实际1280×688（文档694），900×1000实际900×888（文档892）。数字以 observer/release-layout.json 为准。
- 768×1024本轮独立截图及DOM测量顶栏高69px，而非文档所写104px。开局与活动期、小地图展开都分别记录在原始JSON。
- 自述称宽屏留白是当前约束下“最大缩放”，缺乏证据。实现使用包围球与较小FOV的保守拟合；它确保完整入画，但不能证明是投影边界的最紧拟合。报告仅称取景保守、留白较多。
- 自述称“产品CSS未因该假阳性做错误改动”，带有事后解释。时间线显示16:06:38在第一次假阳性后新增banner-zone、缩小banner盒体，16:09才修正DOMRect字段。本次样式改变没有造成已观察到的产品缺陷，但不能据此证明当时诊断正确。
- 自述两次单跑后将 smoke 超时称为“偶发确认”，只能确认失败不稳定复现，不能据此确定浏览器调度、GPU或其他原因。独立自然局和布局检查未遇到该超时；根因仍未定。
- “任何尺寸/宽高比”属于外推；实测仅覆盖1440×900、1280×800、900×1000、768×1024及它们之间的游戏中重排，不代表手机触控或极小窗口。

功能结论仍成立：独立上下栏与展开小地图未与战场相交，四敌模型完整入画，真实输入战斗和缩放后的鼠标求交通过。文档数字与解释可靠性应与实现能力分开评价。
